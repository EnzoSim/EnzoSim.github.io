01

Start here

This guide covers everything Paper's team has shown on YouTube, from the first MCP setup videos in March to the September releases. It is organized so you can learn Paper in order, then come back to look things up. It is also fitted to your work: the examples use your files, the prompts are written for Claude Code with the Paper MCP, and the recommendations come from what your own sessions show.

How the guide is organized

For you. What your sessions say about how you use Paper, the ten changes that would help most, and a four-week plan that tells you which video to watch when. The plan's checkboxes are remembered in this browser.

Learn. Seven chapters, from the canvas to agents and code. Each one opens with its videos, teaches the topic with exact UI names, then ends with exercises on your own files and, where agents are involved, prompts you can paste into Claude Code.

Reference. Keyboard shortcuts, the full Paper MCP tool list, the image models, a glossary, a release timeline, and a searchable library of all 52 videos with their key moments.

A link like ▶ 3:42 opens the video at that second. Use it whenever a step depends on where something sits on screen: the guide describes the interface, the video shows it.

How it was made

  1. Extraction. Metadata, captions (27 written by Paper's team, 25 generated by YouTube), viewer comments, and 1080p video for all 52 videos. From the video: 1,952 frames, one every 2 to 8 seconds, plus 185 contact sheets.
  2. Seven analysts. Seven Opus agents each took one theme (6 to 11 related videos), read every transcript, skimmed every contact sheet, opened the full frames where the screen mattered, and wrote one notes file per video and one chapter per theme.
  3. Reference. An eighth agent read Paper's documentation, its MCP guides, the Paper plugin's two agent skills, and the Paper Shaders library.
  4. Audit. A ninth agent checked coverage (every video and feature lands in a chapter), resolved contradictions against the frames, and fact-checked claims.
  5. Your side. Your project memories, your 14 Paper files, and the 14,018 Paper MCP calls recorded in your Claude sessions between 3 July and 2 October 2026.

Nothing here is a transcript. The chapters are written from the videos, and they cite them, so the exact moment is always one click away.

Three ways to use it

  • One hour. Read Ten changes for you, then watch the first three videos in the plan.
  • The full course. Follow the four-week plan: under an hour of video a week, plus practice on your own files.
  • An answer now. Search the video library, or look up the term in the glossary, which points to the chapter that teaches it.

Ten changes for you

Ordered by how much time they would save you, starting with habits you repeat in every session. Each one says what your sessions show, what to change, and where this guide and the videos teach it.

1. Point at the element instead of describing it

What your sessions show. In 14,018 Paper calls, your agents read your selection once. They spent 2,668 calls (find_nodes, get_tree_summary, get_children, get_node_info) working out which element a description meant, such as "the second card on the Tarifs board".

Change. Select the element in Paper and write "my selection" in the prompt; the agent reads it with get_selection. For a file that is not in front, copy its link with ⌘L and paste it into the prompt, and the agent opens that file before doing anything else.

2. Write feedback as comments and let the agent clear them

What your sessions show. Your feedback arrives in chat, mostly in French and very precise: a misaligned lane, a word that reads oddly, a pill that has to go. Comment tools were called 7 times, and no thread was ever read or resolved.

Canvas, layout and files

This chapter covers how Paper places things (flex layout and constraints), how you move around and select on the canvas, how images and colors are handled, how files are organized, and how boards become PDFs. It draws on six videos published between 2 June and 20 July 2026, so every feature is described as of those dates; later releases may have changed details. Facts taken from the Paper MCP tool descriptions rather than from a video are labelled as such.

1. The mental model

Frames are divs. A frame is a parent container; Paper says outright that a frame is what HTML calls a div. Layers inside a frame are its children, and children of the same frame are siblings ▶ Flex 0:29. Moving a frame moves all of its children ▶ Flex 0:51.

Two kinds of frame. A freeform frame lets children sit at any coordinates. A flex frame places its children from the parent's settings and the siblings around them, so they snap together and adjust when you add or remove layers ▶ Flex 1:06. The layers panel tells them apart: a two-column icon for a horizontal flex frame, a stacked-rows icon for a vertical one ▶ Flex 7:44, and dashed corners for a freeform frame ▶ 8 tips 0:51.

Paper speaks CSS. Paper calls the feature flex, not auto layout, because it is built on HTML and CSS and both agents and developers use the CSS terms ▶ Flex 0:13. For you this means the HTML your agents write with write_html and the Flex section in the panel describe the same thing. The table below is my mapping, not something the videos spell out; check it with get_computed_styles on a node you have set in the panel.

Panel setting CSS your agents write (my mapping)

Two positioning systems. Flex children follow the flex rules. Everything else, meaning children of freeform frames and children with Absolute position ticked inside a flex frame, follows constraints, which decide what happens when the parent is resized ▶ Constraints 0:02.

Sizing modes. The W dropdown lists Fixed, Fit, Fill and Relative ▶ Flex 9:37; H is seen set to fixed values, Fit and Fill across the demos. Fixed holds a value whatever happens around it, and Fit sizes a frame from its contents ▶ Flex 8:37; Fill takes the unused space in the parent ▶ Flex 9:09. Relative is never explained; the closest thing shown is a Stretch constraint turning the width into a percentage (36% on screen) ▶ Constraints 2:44. The size badge under a selection names the mode per axis, for example "Fit 116 × Fit 32" or "Fill 267 × Fit 317"; a bare number means Fixed ▶ Flex 1:44.

3. Procedures

3.1 Make a flex frame

  1. Select the loose layers (Shift-click to add) and press ⇧A, or click "Wrap in flex ⇧A" ▶ Flex 1:22.
  2. To convert an existing freeform frame instead, select the frame and press ⇧A; the button reads "Add flex ⇧A" in that case ▶ 8 tips 0:57.
  3. To group layers without flex, press ⇧F ("Frame selection") ▶ 8 tips 0:42.
  4. Rename the frame by double-clicking its name on the canvas or in the layers panel ▶ Flex 1:44.

After ⇧A the gap was 8 in one demo and 12 in another (a list that was already stacked), so check the value rather than assume it ▶ Flex 1:44 ▶ 8 tips 1:06.

3.2 Set spacing

  1. With the parent selected, set the gap: type it, use arrow keys (Shift for bigger steps), drag the field icon, or drag the pink band between children on the canvas ▶ Flex 2:00.
  2. Set horizontal and vertical padding; click the square icon at the end of the padding row for individual sides ▶ Flex 3:17.
  3. Fills accept tokens: in Fill, pick a token (the demo uses "muted"); the row shows the token name and a detach icon ▶ Flex 3:06.

When you drag a new layer into a flex frame, a blue outline shows the receiving frame and a blue line shows where it will land ▶ Flex 2:28.

3.3 Direction, alignment, space between

  1. Click → for a row or ↓ for a column ▶ Flex 3:57.
  2. Click one of the nine points to align children inside the frame ▶ Flex 4:28.
  3. For Space between, open the sliders icon and choose "Space between", or double-click the nine-point grid ▶ Flex 5:45.

3.4 Split alignment with nesting

Space between spreads every child, so with three children the middle one floats to the center ▶ Flex 6:08. Two patterns fix it:

  • Left group, right item (a row). Shift-select the items that belong together, ⇧A, set their gap. The parent now has two children and Space between pushes them to the edges ▶ Flex 6:18. Stacked text inside the group (name over email) is one more ⇧A with direction ↓ and gap 0 ▶ Flex 7:11.
  • Top group, bottom item (a sidebar). A vertical frame aligned top-left stacks a new child under the others ▶ Flex 7:52. Set the sidebar to Space between, wrap the brand and nav with ⇧A (gap 24); the group stays at the top and the user button at the bottom, whatever the height ▶ Flex 8:08.

3.5 Sizing

  1. Fixed: resize on the canvas, type W or H, or use arrow keys ▶ Flex 8:37.
  2. Fit: pick Fit in the dropdown or double-click the top or bottom edge ▶ Flex 5:06.
  3. Fill: pick Fill in the W dropdown, or Option + double-click the left or right edge ▶ Flex 9:37.
  4. Parent driven by a child: set the parent's W to Fit, then change the child's width; the parent follows, and siblings set to Fill follow the parent ▶ Flex 10:03.

A whole split-view dashboard built this way resizes without breaking, which the video frames as looking right on both a 14-inch and a 16-inch laptop ▶ Flex 10:43.

3.6 Overlays: Absolute position plus constraints

  1. Select the overlay child (a close button in the demo) and tick "Absolute position"; it floats above the content and ignores the flex rules ▶ Flex 11:28.
  2. Hold Option to read distances and place it (16 from the top and right in the demo) ▶ Flex 12:00.
  3. Paper starts it at Left / Top, so it drifts when the parent grows ▶ Constraints 0:27. Pin the right side in the diagram (tooltips read like "Pin top") or choose "Right" in the horizontal dropdown ▶ Constraints 1:05.
  4. Resize the parent to test.

Tokens, color and type

This chapter covers Paper's token system, how color gets into a file, and the typography controls that matter for agent-built designs. It is drawn from seven videos published between 9 June and 21 July 2026, with pointers to the August and September changelogs where a feature announced in June later shipped. Each claim is dated by its video: a June video describes Paper as it was in June.

The mental model

A token is a named value stored in the file. Paper keeps a file's tokens together as its "theme": the menu that copies them between files is called Theme ▶ CSS vars to tokens 3:24. When a property uses a token, the panel shows a chip instead of a raw value. Detaching turns it back into a plain value you can edit freely ▶ CSS vars to tokens 1:17 ▶ Tokens with the team 3:24.

The token types follow Tailwind. Paper supports color, font family, font weight, font size, line height, letter spacing, spacing, breakpoints, containers and radius, and the presenter describes the system as mapping closely to Tailwind ▶ June changelog 0:54. Opacity tokens arrived later and can be paired with a color token on the same fill ▶ September changelog 1:52 ▶ September changelog 2:05.

Names keep their CSS form; pickers shorten them. An agent creating tokens from code or from a design uses CSS-variable names such as --color-accent, --text-7xl or --container-page ▶ Tokens with the team 2:40. The color picker lists them without the namespace ("accent", "blue-3") ▶ Tokens with the team 2:24 ▶ CSS vars to tokens 1:12. The size dropdown shows "lg 13", and hovering the field shows "text-lg" ▶ CSS vars to tokens 2:50 ▶ CSS vars to tokens 3:00.

Agents bind tokens through var(). Paper's canvas is HTML and CSS, and agents build boards with Write Html calls ▶ CSS vars to tokens 2:01. Their HTML references tokens as var(--name). The agent described its style guide as "wired" to the tokens that way ▶ Tokens with the team 2:40. When a token later changed value and name, every bound element followed, style guide included ▶ Tokens with the team 7:52 ▶ Tokens with the team 8:02. This is the main reason to create tokens before an agent writes HTML: literal values do not follow later token changes ▶ Tokens with the team 8:00.

Aliases are allowed. Semantic tokens can point at palette tokens through var(); the import kept aliases like --color-popup pointing at their base token ▶ CSS vars to tokens 0:56. The palette must exist before the aliases that reference it ▶ June changelog 0:32.

Tokens are per file, and there were no modes in June. Moving tokens to another file is a copy and paste through the Theme menu, while shared libraries are still in progress ▶ CSS vars to tokens 3:08. Light and dark pairs written with light-dark() were imported with their light value only ▶ CSS vars to tokens 0:56. Themes and modes were "in progress" at the end of June ▶ June changelog 1:06. The team described modes as light, dark and possibly contrast, and theme classes as bundled styles: a heading style such as H1, or a card style combining shadows, borders and radius ▶ Tokens with the team 9:11 ▶ Tokens with the team 9:22 ▶ Tokens with the team 9:32. The token docs (paper.design/docs/tokens, linked from the video) hold the roadmap ▶ CSS vars to tokens 3:58.

The mental model

  • A shader is a layer. It sits in the layers list under its type name (Warp, Fluted Glass, Pulsing Border) with its own icon, and it keeps the normal layer properties: Layout, Radius, Blending, Fill, Outline, Border, Shadow ▶ Shaders tour 0:22. Later builds also list Inner shadow, Filters, Video and Export under it ▶ Logo shaders 7:20. You size it, round it, nest it and reorder it like a frame.
  • On top of that sits a shader block: Presets, sometimes an input (Image or Shape), Parameters, and one or more color lists (Foreground, Colors, Tint, Inner) ▶ Logo shaders 0:56.
  • Three families, matching the picker's three sections. Image filters transform an image you feed them ▶ Shaders tour 1:32. Logo animations react to the geometry of a shape you supply ▶ Logo shaders 0:44. Effects generate patterns from parameters alone, Warp and Pulsing Border among them ▶ Resend button 1:06.
  • Everything moves by default. Speed drives the animation; at 0% the shader becomes a still texture ▶ Shaders tour 1:00.
  • Presets are starting points. Picking one rewrites all parameter values; you tune from there ▶ Shaders tour 0:50.
  • The eyedropper is the connector. In an Image or Shape input it captures any canvas layer, including text, logos and other shaders ▶ Shaders tour 2:09 ▶ Halftone text 0:10 ▶ Logo shaders 1:08. In a color list it picks colors from another element ▶ Resend button 1:32. Captured inputs are stored as .webp files named after the source layer, such as "Paper Logo.webp" or "Fluted Glass.webp" ▶ Logo shaders 1:20 ▶ Shaders tour 3:30.
  • The code is the shader. Right-click, Copy as React CSS gives a component from the @paper-design/shaders-react package with every parameter as a prop, and Paper says it is the same code that renders the shader on the canvas ▶ Shaders tour 1:12. Panel percentages become decimals in the props (Speed 350% is written 3.5, Scale 247% is 2.47) ▶ Shaders tour 1:24. Since July 2026 Paper Shaders are open source and free to use in sites, apps, templates and plugins ▶ Logo shaders 0:02.

Advanced techniques

  • Contour is the logo knob. Every pixel of a logo animation knows its distance to the shape's edge, and Contour sets how far in pixels still react: 0% is a plain mask with no edge reaction, 18% hugs the rim, 100% floods the interior with edge-following bands ▶ Contour 0:20 ▶ Contour 0:28 ▶ Contour 0:38. Harcourt settles on 40% for Liquid Metal ▶ Logo shaders 4:25.
  • Inner glow vs Outer glow. Inner glow works inside the shape's bounds, Outer glow outside; lowering Scale reveals more of the outer glow ▶ Logo shaders 2:02. Next to text, set Outer glow to 0% so the copy stays legible ▶ Logo shaders 7:35.
  • Grain and direction. On Heatmap, Noise adds a grain texture (keep it low) and Angle turns the direction of the effect, 45° in the demo ▶ Logo shaders 1:18.
  • Still graphic shapes. Speed 0% with Softness 0% turns Warp into hard-edged, poster-like shapes ▶ Shaders tour 1:06.
  • Vectorize flat art. Right-click a flat image and choose Vectorize; an AI model turns it into an SVG layer ("Vector") that scales to 3558 x 3558 without visible loss ▶ Shaders tour 3:58 ▶ Shaders tour 4:15. It is a companion to shaders for poster work, not a shader itself.
  • Chains. Any shader can be the input of an image filter, so looks can be stacked: glass, then halftone ▶ Shaders tour 3:12.
  • Hard edges by layer order. Thickness alone only hardens the outer edge; an opaque content frame in front of the shader hardens the inner edge too ▶ Resend button 3:20.
  • Clip content for smoke. Smoke and glow shaders spill past their frame unless the parent clips ▶ Logo shaders 6:55.
  • Name sources before capturing. Captured inputs inherit the source layer's name ("Paper Logo.webp", "Vercel Logo.webp"), so clean names make chains readable later ▶ Logo shaders 5:46.
  • Type exact colors. The color picker takes OKLCH, HSL, RGB and hex, so token colors can be entered exactly instead of sampled ▶ Cloudflare loader 1:12.
  • Code as documentation. Pasting the copied React code next to the shader on the canvas, as Stephen does, keeps the exact values visible in the file ▶ Shaders tour 1:24.

Pitfalls and limits

  • Flex parents. A shader dropped into a flex frame is laid out next to the content until you check Absolute position ▶ Resend button 2:56.
  • Spill. Without Clip content on the parent, smoke escapes the frame ▶ Logo shaders 6:55.
  • Presets overwrite. Clicking a preset after tuning replaces your values ▶ Shaders tour 0:50.
  • Overload. Outer glow and Repetition overwhelm fast; Repetition at 1000% was "visually overwhelming" and went back to 200% ▶ Logo shaders 4:46.
  • Legibility on type. Text effects break the glyph at the extremes: halftone dots at maximum Size melt the letter into a blob ▶ Halftone text 0:26, and strong lens settings smear a headline ▶ Lens Distortion 0:20.
  • Captures are files. Inputs are stored as .webp captures. Whether they refresh when the source changes is not shown, so re-capture after editing a source layer.
  • Disabled commands. Vectorize and Remove background are greyed out on a shader's context menu ▶ Shaders tour 1:12; Vectorize applies to images and works best on flat ones ▶ Shaders tour 4:05.
  • React only. The code export shown targets React, with the package version pinned in the header comment ▶ Shaders tour 1:24. No vanilla JS export appears in these videos. The npm package also works without React: see Paper Shaders, in Paper and in code.
  • No custom shaders. You work with Paper's catalogue; a viewer's question about writing custom shader code got no answer (▶ Shaders tour, comments).
  • Plan gating. Video export is a Pro plan feature (▶ Logo shaders, comments).
  • Resizing. There is no aspect ratio lock; hold Shift while dragging to keep proportions (Paper team reply, ▶ Resend button, comments). A Scale tool was promised as coming soon in a team reply under the logo shaders video and is listed as coming next in September ▶ Sep changelog 4:49.
  • Noise. Among logo animations only Heatmap shows a Noise parameter; a viewer's request to add it to the others got an emoji, not a commitment (▶ Logo shaders, comments).
  • Layer order. In the Resend demo, placing the shader above the content frame in the layers list rendered it behind; the list seems to follow DOM order, the reverse of Figma's habit (inference from one example). Check the canvas after reordering.
  • Agents. None of these videos show the Paper MCP reading or writing shader parameters. Plan for manual shader tuning and verify what your agent can see before relying on it (see the first prompt recipe).

The mental model

The canvas is HTML and CSS. Paper uses HTML and CSS as its rendering engine, which agents already write fluently. Tools with their own rendering engine cost agents more tokens and time and give lower accuracy ▶ Connected canvas 0:14. This is why write_html is the natural way in. It also explains where writes lose fidelity: CSS with no equivalent in Paper's node model. Your own sessions list those edges (backdrop-filter, repeating-linear-gradient, transform: scale, styled inline spans, empty divs).

Agents read and write. Reading means the canvas is visual context next to your prompt: reference images, a pasted draft, your manual edits ▶ Teams with agents 0:16. Writing means drafts, many variations to choose from, and boilerplate such as applying styles or renaming layers ▶ Teams with agents 0:38. The designer keeps the decisions.

The server lives in the desktop app. The videos show a local server named paper at http://127.0.0.1:29979/mcp ▶ Cursor setup 1:00. It works only while Paper Desktop is running with a design file open ▶ Cursor setup 1:08. A Paper file in the browser does not count, and neither does the desktop dashboard alone ▶ Claude Code setup 1:36. It is a local port, so there is no account token involved (a viewer's answer under ▶ Cursor setup), which is also why your scripts can call the same endpoint directly.

The plugin is more than the server. As shown in May 2026, the paper-desktop plugin bundled the server, two skills (code-to-design and design-to-code, callable with / or used automatically) and an auto-applied rule, ensure-paper-started, that reminds the agent to keep Paper open ▶ Cursor setup 1:00. Connecting an agent

  • The MCP server runs inside Paper Desktop. Opening Desktop starts it in the background, and it reads and writes the file that is open (paper.design/docs/mcp; paper.design/docs/support). An agent edits only the open file, so check that the right file is open (paper.design/docs/support). Since August 2026 agents can also work across several open files, including background tabs (build log, Aug 2026).
  • Two transports. 1. Stdio through the Paper CLI (current recommendation): the agent launches /path/to/paper mcp, which relays to Desktop. The agent can see Paper's tools and instructions even while Desktop is closed, and no localhost URL has to be pasted (paper.design/docs/mcp). The CLI path is copied from the MCP panel in Desktop (paper.design/docs/mcp). On this Mac it is ~/.paper/bin/paper (Paper CLI; Claude extensions list). 2. Streamable HTTP at http://127.0.0.1:29979/mcp (older setup). Desktop still serves it while a file is open, so existing HTTP configs keep working (paper.design/docs/mcp). In the bundle, port 29979 and path /mcp are constants, served by a Hono HTTP server with a streamable HTTP transport, and the server identifies itself as paper-desktop with the app version (Paper Desktop app).
  • Paper Web (browser) offers no local MCP. Since September 2026 it supports WebMCP for in-browser agents (build log, Sep 2026). The partner example embeds Paper in an iframe (permissions tools; clipboard-read; clipboard-write; local-fonts) and calls document.modelContext.getTools() / executeTool(). It needs Chrome 150+ and the WebMCP origin trial, and Paper must allowlist the origin ("available for Paper partners") (github.com/paper-design/webmcp-agent-example).
  • One-click setup in the app (Sep 2026): the Connect your agent button in the editor's right panel opens a panel where you pick a harness and click "Add to …" (build log, Sep 2026; ▶ New in Paper, Sep 0:56). The bundle's installer handles claude-code, codex-cli, chatgpt, github-copilot, opencode and antigravity; a vim id also appears, possibly only in tests. Its tests show it replaces an existing HTTP paper entry with a stdio entry, for example in ~/.claude.json (Paper Desktop app).

How agents are told to work in Paper

  • Load get_guide("paper-mcp-instructions") once per session, before other tools; reload it in long threads (MCP server instructions).
  • Start with get_basic_info; use get_selection for the user's focus. Omitting fileId targets the viewed file; omitting pageId targets the viewed page. Passing a pageId lets the agent work elsewhere without disturbing the user, but the agent cannot switch the user's page (MCP server instructions; MCP guide). The May 2026 changelog says agents can change pages within a file (build log, May 2026); the current guide says they cannot switch the viewed page.
  • Every file-scoped tool returns a file header with file id, name and a contentHash of the tokens. Check the file id, and re-read tokens if the hash changed (MCP guide).
  • Typography: call get_font_family_info before the first text styling of a session; prefer fonts already in the file; font size in px, letter-spacing in em, line-height in px (MCP server instructions; MCP guide).
  • New designs: post a brief to the user before any mutation. The brief lists mood candidates, the chosen mood (deliberately not the first instinct), 5–6 palette hex values with roles, type scale and direction (MCP guide, "Before Creating New Designs").
  • Build small: one visual group per write_html; more than about 15 lines of HTML means split it; never batch a whole component. Clone existing nodes with <x-paper-clone node-id="…" style="…"/>. Prefer duplicate_nodes + update_styles + set_text_content when that is cheaper (MCP guide; MCP schema).
  • Review checkpoints are mandatory: after each section, take a screenshot and give a one-line verdict on spacing, typography, contrast, alignment, artboard fit and repetition. Fix things in place; do not start over. If content clips, set the artboard to height: "fit-content"; never guess a fixed height (MCP guide; MCP server instructions).
  • Repeated rows need fixed-width slots (width + flexShrink: 0) for icons and trailing actions; check the vertical lanes with a screenshot after 3+ rows (MCP guide; MCP server instructions).
  • Always call finish_working_on_nodes when done; pass specific artboard ids when other agents are active (MCP server instructions; MCP schema). An artboard being worked on shows a dot pattern above it (▶ Claude Code setup 2:42).
  • Never show raw node IDs to the user (MCP server instructions; MCP guide).
  • Design to code: use get_jsx, get_computed_styles and get_fill_image for exact values, never screenshots; translate to the codebase's conventions (MCP guide; MCP server instructions).
  • Tokens: always use existing tokens through var(--…). New token sets follow Tailwind v4 namespaces (--color-*, --breakpoint-*, --spacing-*, --container-*, --opacity-*, --font-*, --font-weight-*, --text-*, --tracking-* (em), --leading-* (px), --radius-*). Token opacity: color-mix(var(--color-x) 40%, transparent) or with an opacity token (MCP guide).
  • Default artboard sizes: Desktop 1440×900, Tablet 768×1024, Mobile 390×844 with the status bar. Artboards default to flex column and are auto-placed; leave 80 px between artboards when positioning them (MCP schema). The guide's step 1 says mobile is 375 wide, which conflicts with 390 in the tool description (MCP guide).
  • Design-quality doctrine (paraphrased): minimalism with a warm human touch; deliberate spacing; asymmetry and scale contrast; Swiss-editorial punchy type with heavy display and light labels; light mode by default; information on surfaces rather than everything in cards; avoid late-2010s gradients and shadows; one intense color moment. Choose a mood word, then derive every color from objects in that scene. The guide lists 19 proven ground × accent pairings, among them editorial (pure white × cobalt), hypertext (pure white × hyperlink blue) and maritime (fog gray × deep navy). Pairings to avoid: warm off-white with red/orange/terracotta; warm off-white with fluorescents; dark navy or charcoal with electric purple, lime or teal; pure white with muted earth tones; tinted warm grounds with saturated accents. Pure white #FFFFFF is the normal ground for SaaS dashboards. Text contrast is non-negotiable, and text of 12 px or less is acceptable only in dense productivity UIs. Placeholder content must be realistic and must never mention Figma or Sketch (MCP guide, "Design Quality").
  • Mobile status bar: paste the guide's ready-made Apple status bar (9:41 in system-ui 17/600, plus an 82×22 SVG of signal, wifi and battery) as the first child; change only its color (white by default, black on light grounds); omit it only for full-screen experiences (MCP guide; MCP schema).
  • Figma import: write_html understands only literal CSS. Resolve every Figma variable, token or Tailwind class to a concrete value. Inline asset URLs; the Figma MCP's http://localhost:3845/assets/… URLs are valid. Tiled backgrounds go on a div with background-repeat. For instance node ids like I700:1100;2000:1000, use the last segment (MCP guide).

HTML and CSS that Paper accepts

Supported or recommended - Inline styles (style="…") are the only styling input (MCP schema; paper.design/docs/paste/html). - Layout: flexbox, padding and gap are the core tools; flex wrap since Aug 2026, with per-axis wrap gap since Sep 2026; negative gap since Jun 2026 (MCP schema; build log, Aug 2026; build log, Jun 2026; ▶ New in Paper, Sep 3:22). - Absolute positioning is fully supported. Use it for decoration and never cover the whole artboard with one absolute element, because that blocks the cursor (MCP schema). Elements can ignore flex layout (absolute option, Nov 2025), and a Constraints panel handles parent resizes (Mar 2026) (build log, 19 Nov 2025; build log, Mar 2026). - Sizing: border-box everywhere; fit-content heights; fill and fit by double-click (MCP schema; build log, Mar 2026). - display: block is fine for simple text or decorative shapes, not for layout containers (MCP schema). - Colors: hex, rgb(a), hsl(a), oklch, oklab; sRGB and Display P3 side by side; color-mix() on tokens (MCP schema; paper.design/compare/figma; MCP guide). - Design tokens as CSS variables, including inside SVG fill and stroke (MCP guide; MCP schema). - Fonts: all Google Fonts and locally installed fonts by family name (MCP schema). Variable font axes, automatic optical size, OpenType features (build log, 19 Nov 2025; build log, 19 Dec 2025; build log, Mar 2026). - Fills and effects: gradients, including text gradients and on-canvas editing; image fills composed with other fills; shadows, outlines, borders, blend modes; filters (blur, saturate, grayscale, brightness, sepia, invert, hue-rotate); backdrop filters; text stroke (build log, 26 Sep 2025; build log, 6 Nov 2025; build log, 19 Dec 2025; build log, 19 Jan 2026; build log, Mar 2026; build log, Apr 2026; paper.design/compare/figma). - Text formatting: casing, wrapping, truncation; CJK word-keeping (build log, 19 Dec 2025; build log, Sep 2026). Code blocks use <pre> or white-space: pre as a single element with one color (MCP schema). - SVG: inline SVG, pasted SVG, path editing (MCP guide; paper.design/docs/svg). - Paper-specific attributes and elements: layer-name="…", data-paper-locked, hidden, <x-paper-clone node-id="…">; local images through paper-asset:///absolute/path; AI images through paper-gen:// (paper.design/docs/paste/html; MCP schema). - Images from <img> and background-image are uploaded into Paper when pasting HTML (paper.design/docs/paste/html). HEIC/HEIF are accepted (build log, 19 Jan 2026). - Styles that Paper renders but cannot edit in its panels appear in an "Other styles" panel (build log, May 2026).

Not supported or to avoid - margin, display: inline, display: grid and HTML tables: do not use them; use padding and gap (MCP schema). CSS Grid is "Planned" on the roadmap (paper.design/roadmap), although the Sep 2026 release added alignment and gap controls for grid elements (▶ New in Paper, Sep 3:38). - Classes, selectors, <style> tags and external stylesheets: class names are dropped and selector styles ignored (paper.design/docs/paste/html). - Rich text, meaning several styles in one text node: not supported yet; announced as coming soon (paper.design/docs/paste/html; MCP schema; ▶ New in Paper, Sep 4:59). When pasting, a block with inline children flattens into one text node, inline elements become inline-block, and inputs become frames with text children (paper.design/docs/paste/html). - Emojis as icons: use SVG instead (MCP schema). - Unresolved references (var() to tokens that do not exist in Paper, Tailwind classes) fail silently or break the output when importing (MCP guide). - Styles that do nothing in a node's context are dropped and reported in ignoredStyles (MCP schema). - Figma paste limits: components, instances and variables are detached; masks hidden; no rich text; no noise, texture or glass effects; no arbitrary dash lengths or gradient strokes; limited pass-through blending; no symmetry or repeat effects; diamond gradients become radial. Image import needs a connected Figma account and is subject to Figma API rate limits (paper.design/docs/paste/figma). - Pseudo-elements, CSS transforms, <video>/<iframe> in write_html: not documented (paper.design/docs/paste/html). - Behaviors seen in your sessions (not in the docs): write_html replace drops children's absolute positioning; empty divs are ignored; styled inline spans are ignored; backdrop-filter bleeds; repeating-linear-gradient and transform: scale did not render; rotation pivots on the top-left corner; native PDF export failed on report pages (your sessions).

Driving Paper from scripts

The Paper desktop plugin's MCP server also listens over Streamable HTTP at http://127.0.0.1:29979/mcp. A small client (POST initialize, keep the Mcp-Session-Id header, POST notifications/initialized, then tools/call with a fileId) calls the same tools as your agent, but reads long HTML from files so it lands byte for byte. It is also the way back in when the session's MCP bridge reports "not connected" because Paper was closed when the session started; restarting the agent session restores the official bridge. Print every text block of each response: validation notes arrive in a separate block.

  • Absolute position. Takes a child out of its flex parent's flow so it floats; pin it with constraints. Canvas

  • Clip content (⌥C). Hides what overflows a frame; smoke and glow shaders need it on their parent. Canvas
  • code-to-design, design-to-code. The two agent skills shipped in the Paper plugin v0.1.0, dropped in v0.2.1. The plugin's two skills
  • Comments (C). Pins with replies, reactions and resolve. Agents can list, read and resolve them, not create them. Snapshot and collaboration, Agents
  • Connect your agent. The button in the right panel's MCP section (September 2026) that installs a stdio connection for your agent. Connecting an agent
  • Constraints. Left, Right, Left + Right, Center or Stretch: how a non-flex layer behaves when its parent is resized. Canvas
  • Contour. The logo-shader setting for how far in from the edge the effect reacts. Shaders
  • Copy as PNG, Tailwind, React CSS (⇧⌘C, ⌥T, ⌥R). Copies a layer as an image or as code. Code
  • Create image (⇧⌘I), Create SVG (⇧⌘J). The AI generation panels, each with a model picker. Vectors and images
